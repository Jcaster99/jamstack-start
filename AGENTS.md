# AGENTS.md

Guide for coding agents working in this repository. Read it before changing code.

## What this is

A multilingual, content-driven website on **Cloudflare Workers**:

- **TanStack Start** (React 19, SSR, file-based routing) with the **React Compiler**
- **Lingui** for UI strings, via `@sourceking/tanstack-lingui` (locale in the URL)
- **Content Collections** turns `content/` (YAML / Markdown) into typed data at build time
- **Sveltia CMS** at `/admin` edits `content/` through GitHub, using the OAuth proxy in `src/routes/api/auth/`
- **Tailwind CSS v4**, **Biome**, **bun**

Locales: `en` (default, no URL prefix), `zh`, `ja`, `th`, `es` → `/`, `/zh/...`, `/ja/...`.

| Type check (also generates content types) | `bun run typecheck` |

| Run the production build locally (workerd) | `bun run preview` |

**Before you say a change is done**, run `bun run typecheck`, `bun run check`, `bun run i18n:check` and `bun run build`. If you touched `public/admin/config.yml`, also run `bun run validate:cms`.

## Layout

```
content/                      # CMS-managed data (edited by humans through /admin)
  authors/<slug>.yaml
  posts/<locale>/<slug>.md    # same <slug> in each locale folder = one translated post
content-collections.ts        # registers collections
src/
  content/                    # collection schemas (zod) + transforms; run at build time, outside Vite
  server/                     # createServerFn queries over the collections
  routes/
    __root.tsx                # html shell, head, 404
    {-$locale}/               # every page lives here (optional locale prefix)
      route.tsx               # validates the locale, puts it in context, syncs i18n with the URL
    api/auth/                 # OAuth proxy for Sveltia CMS (GitHub/GitLab)
  layouts/AppLayout.tsx       # header, nav, language switcher
  libs/
    locales.ts                # locale list (framework-free, also imported by src/content)
    i18n.ts                   # Lingui + router integration (LocalizedLink, useLocale, ...)
    auth.ts                   # OAuth helpers
  locales/<locale>.json       # Lingui catalogs (en.json is the source)
  server.tsx                  # Worker entry: /en/... → / redirects
  start.ts                    # request middleware (CSRF for server fns, i18n)
public/admin/                 # Sveltia CMS (index.html + config.yml)
public/uploads/               # media uploaded from the CMS
```

## Rules

### Routing and locale

- Put pages under `src/routes/{-$locale}/`. Never create routes outside it except `api/`.
- Read the locale in loaders from **`context.locale`** (set from the URL in `{-$locale}/route.tsx`). Do not read it from cookies or `i18n.locale`.
- Link with **`LocalizedLink`** from `#/libs/i18n`, never a bare `Link`/`<a>` to internal pages. It adds the locale prefix. Its `to` is typed as `string`, so a typo does not fail typecheck: check the target route exists.
- `src/routeTree.gen.ts` is generated by the Vite plugin. Never edit it. Do not run `tsr generate`.

### UI strings (Lingui)

Full rules are in the `i18n-lingui` skill. The essentials:

- Every visible string, including `alt`, `placeholder` and `aria-label`, goes through `i18n._()` with `useLingui()` from **`@lingui/react`**. The argument is a full English **string literal**, and that literal is the message ID:
  ```tsx
  import { useLingui } from "@lingui/react";
  const { i18n } = useLingui();
  <h1>{i18n._("Authors ({count})", { count })}</h1>
  ```
- Labels declared at module level (nav items, status maps) use `msg({ id: "..." })` from `@lingui/core/macro` and are rendered with `i18n._(descriptor)`. See `src/layouts/AppLayout.tsx`.
- Do not use `<Trans>` or the `t` macro. Never build messages by concatenation or template strings.
- Format numbers and dates with `#/libs/intl` (`formatDate(i18n.locale, value)` ...), never `i18n.number` / `i18n.date`.
- After changing text, run `bun run i18n:extract`, fill **every** catalog in `src/locales/` (`zh`, `ja`, `th`, `es`), then run `bun run i18n:check`.

### Content

- Pages read content **only through server functions** in `src/server/` called from a route `loader`. Do not import `content-collections` in components or routes: that bundles the data into client JavaScript.
- Return only the fields the page renders (strip `_meta`, raw `content`).
- A collection is defined twice and both must stay in sync: the zod schema in `src/content/<name>.ts` and the CMS collection in `public/admin/config.yml` (same folder, same fields, matching validation such as `type: url`).
- Files in `src/content/` run in Node at build time, not in Vite: import only framework-free modules (e.g. `../libs/locales`), never `#/libs/i18n` or React.
- In transforms, `context.documents(otherCollection)` returns **pre-transform** documents: match on `_meta.path`, not on fields added by a transform.
- Markdown is compiled at build time with `rehype-sanitize`. Keep sanitizing; the HTML is rendered with `dangerouslySetInnerHTML`.
- Dates: use `isoDate()` from `src/content/helpers.ts` (date-times without an offset are treated as UTC). Format with `formatDate(locale, value)` from `#/libs/intl` (UTC time zone by default, safe for hydration).
- Optional CMS fields arrive as `""`: use `optionalString()`, `optionalUrl()` and `optionalEmail()` from `src/content/helpers.ts`.

### Runtime (Cloudflare Workers)

- Secrets and vars come from `process.env` (Workers `nodejs_compat`). Locally they live in `.dev.vars` (copy `.dev.vars.example`). Never commit `.dev.vars` or `.env*`.
- No Node-only APIs (fs, child_process) in code that runs in the Worker.
- The OAuth proxy must stay on the same origin as `/admin`. Keep the `state` cookie check and the origin check on `postMessage` in `src/routes/api/auth/callback.ts`.

### Style

- Biome: tabs, double quotes. Imports are sorted by Biome. Use the `#/` alias for `src/`.
- Conventional Commits are enforced (`feat:`, `fix:`, `chore:`, ...). Hooks run Biome on commit and typecheck on push.
- Match the surrounding code; keep comments for the non-obvious why.
